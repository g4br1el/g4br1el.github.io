Three ideas that do most of the work:
  1. A scale must factor out of the integer sum. Per-token (activation rows) and per-output-channel (weight rows) scales are free in an INT8 GEMM. Per-input-channel scales are not, because they index the reduction dimension k. This is exactly why channel-wise activation outliers hurt.
  2. SmoothQuant moves that per-channel difficulty from X into W, exactly. It uses XWT = (X·diag(s)−1)(W·diag(s))T and folds s into the previous op (norm γ, V-projection, up-projection) offline.
  3. QAT = fake quantization + a straight-through estimator. Learn the step size (LSQ). Use QAT when PTQ fails: at low bit widths, on fixed-function INT8 hardware, or for small models with no redundancy.

1. Affine quantization from first principles

q = clamp(round(x / s) + z, qmin, qmax)   ·   x̂ = s · (q − z)
SchemeParametersWhy
Symmetric, restricted range (INT8)z = 0, s = amax/127, q ∈ [−127, 127]Zero-points disappear from the GEMM. It wastes one of 256 codes (−128) but keeps the range symmetric, so −q is always representable. This is the standard choice for weights.
Asymmetric (UINT8)s = (max − min)/255, z = round(−min/s)Uses the whole range for skewed data such as post-ReLU or post-GELU activations. The integer z makes 0.0 exactly representable, so padding and ReLU zeros stay exact.

2. Error model

2.1 Rounding noise: s²/12

Inside the range, if s is small relative to the signal, the error e = x̂ − x is approximately uniform on [−s/2, s/2]:

E[e²] = (1/s) ∫−s/2s/2 e² de = s²/12

2.2 About 6 dB per bit

Take a full-scale uniform signal on [−A, A] with b bits:

  • s = 2A/2b
  • signal power = A²/3
  • noise power = A²/(3·22b)
SQNR = 22b  →  20·log10(2)·b ≈ 6.02·b dB

Gaussian example: with min-max scaling over 10⁶ samples, amax ≈ 4.9σ. At 8 bits, SQNR = 10·log10(12·127²/4.9²) ≈ 39 dB.

Add a single outlier at 60:

  • s = 60/127 = 0.47 and SQNR ≈ 17 dB.
  • Typical values with |x| ≤ 1 now land on q ∈ {−2, …, 2}. That is about 2.3 effective bits.

2.3 Clipping versus rounding

If you clip at c < amax:

  • The rounding MSE (∝ c²) shrinks.
  • The clipping MSE, E[(|x| − c)²; |x| > c], grows.
MSE(c) = c²/(3·qmax²) · P(|x| ≤ c)  +  E[(|x| − c)²; |x| > c]

The optimum c* lies inside the range, and it moves further below amax as the bit width drops and the tails get heavier. At 4 bits, clipping is not optional.

2.4 Propagating through a GEMM

With y = Σk xkwk, x̂ = x + ex and ŵ = w + ew, independent zero-mean errors, and the exew term dropped:

Var(Δy) ≈ K · ( E[w²] · sx²/12  +  E[x²] · sw²/12 )

This is the variance lemma from Lesson 7 again. It uses E[x²], not Var(x), which matters for non-zero-mean post-ReLU inputs. Activation and weight error contribute additively, so the worse of the two dominates. That is why "balance the difficulty" (SmoothQuant) is the right goal.

3. Granularity and the GEMM constraint (the key insight)

Consider Y = XWT with X ∈ ℝT×K (tokens × input channels) and W ∈ ℝN×K (output × input channels). With a token scale at and a channel scale bn:

Y[t,n] = Σk X[t,k]·W[n,k] ≈ Σk atqX[t,k] · bnqW[n,k] = at·bn · Σk qX[t,k]·qW[n,k]

The integer sum runs on INT8 Tensor Cores with INT32 accumulation, and atbn is applied once in the epilogue. A scale ck that depends on k cannot be pulled out of the sum, so it would need a float multiply inside the reduction.

So every row's amax is set by the outlier channels, and per-token scaling barely helps. The structure is per-channel, and per-channel is the one granularity the GEMM forbids for X.

4. Calibration (post-training quantization)

Weights are always quantized statically, from their own values. Activations need statistics from about 128–512 representative samples, run through the same preprocessing pipeline as deployment.

  • Static vs dynamic activations.
    • Static: fixed scales and zero runtime cost, but brittle when the deployment distribution shifts.
    • Dynamic per-token: one amax reduction per row at runtime, fused into the preceding norm kernel. This is the norm for LLMs.
  • BN folding (Lesson 8) happens before weight quantization:
    W′c = Wc · γc/√(σc² + ε),   b′c = βc + (bc − μc) · γc/√(σc² + ε)
    Channels with tiny σc get huge folded weights. The per-channel spread can reach 100× or more (MobileNet depthwise convs), which forces per-channel weight scales or cross-layer equalization. CLE is SmoothQuant's ancestor for ReLU networks [verify: Nagel et al. 2019].
  • Bias correction. Weight quantization error shifts the output mean by ΔW·E[x]. Subtract that from the bias [verify: DFQ].
  • Sensitivity analysis. Quantize one layer at a time and rank the layers by output SQNR or task metric. The usual suspects are kept in higher precision: the first conv, the last layer or lm_head, softmax, and norms.

5. LLM outliers and SmoothQuant

5.1 The phenomenon

Beyond a few billion parameters, a handful of hidden channels carry activations about 20× or more larger than the rest. They appear systematically, in the same channels across tokens and layers [verify: LLM.int8(), Dettmers et al. 2022, ~6.7B onset]. Weights are well-behaved. Activations are hard to quantize; weights are easy.

5.2 Derivation

For any positive vector s ∈ ℝK:

Y = XWT = (X · diag(s)−1) · (W · diag(s))T  =  X̂ ŴT

This is mathematically exact in exact arithmetic. SmoothQuant chooses, per input channel j:

sj = max|Xj|α / max|Wj|1−α

Here max|Wj| is the max over column j of W. The new channel maxima are:

max|X̂j| = max|Xj|1−α · max|Wj|1−α,    max|Ŵj| = max|Xj|α · max|Wj|α

At α = 0.5 both equal √(max|Xj|·max|Wj|), so the difficulty is split evenly. α = 1 moves all of it into W, which is exactly the "per-input-channel X scale moved into W" from §3. The paper's default is α = 0.5, with larger values for models with stronger outliers [verify: 0.75–0.85 for some].

5.3 Worked example (α = 0.5)

The spread across activation channels drops from 64× to 8× (= √64). The weights take on an 8× column spread. Since weights use per-output-channel scales and started out flat, they can absorb it.

6. QAT: fake quantization, STE, LSQ

6.1 Fake quantization

Simulate quantization in float during training:

x̂ = s · round(clamp(x/s, −Qn, Qp))

The forward pass sees exactly the quantized values. The problem is the backward pass: d round/dx = 0 almost everywhere.

6.2 Straight-through estimator (STE)

Treat round as the identity in the backward pass. With the clamp kept, this gives the "clipped STE":

∂x̂/∂x ≈ 1 if −Qn ≤ x/s ≤ Qp,   else 0

In PyTorch: x + (torch.round(x) - x).detach(). Intuition: the forward pass sees the quantized network, and the gradient is the one for the nearby float network. Weights drift until they settle in a good rounding cell.

6.3 LSQ: learn the step size

Differentiate x̂ with respect to s, using STE for round:

∂x̂/∂s = round(x/s) − x/s  (inside the range),    −Qn or +Qp  (clipped)
  • Inside the range: the gradient is the signed rounding residual, so s learns to balance rounding error.
  • Clipped values: they push s up. The equilibrium is the learned clip, a trainable version of §2.3.

LSQ details [verify: Esser et al. 2019]:

  • Initialization: s = 2⟨|x|⟩/√Qp.
  • Gradient scale: g = 1/√(N·Qp).
  • Note: with Adam, a constant gradient scale largely cancels out, because Adam normalizes per parameter. g matters mainly for SGD.

6.4 Practical recipe

  • Start from a converged FP checkpoint, never from scratch. Fine-tune for a small fraction of the original schedule with a learning rate about 10–100× lower [verify].
  • Calibrate first, so that QAT starts from PTQ quality. Freeze the observers or BN statistics after a while, and fold BN during QAT to match deployment [verify: Jacob et al. 2018].
  • Watch for weight oscillation across rounding boundaries late in training. It corrupts BN statistics and final accuracy. Remedies are freezing or dampening [verify: Nagel et al. 2022].
SituationChoice
W8A8, large model, flexible kernelsPTQ (+ SmoothQuant). QAT is rarely worth the cost.

W4A4, or small CNNs and detectors at INT8 on an edge NPU with per-tensor activationsQAT
No training data or pipeline accessPTQ only, plus data-free tricks (CLE, bias correction)

7. Systems angle

7.1 The W8A8 inference pipeline

  1. Quantize activations: per-token amax, scale and cast to INT8, fused into the RMSNorm kernel.
  2. Multiply: INT8 × INT8 → INT32 MMA on Tensor Cores.
  3. Epilogue: acc · at · bn + bias, then BF16 output or requantization to INT8, fused into the GEMM. Unfused quantize and dequantize kernels can eat the entire speedup.

7.2 INT32 accumulation bound

Worst case: K · 127 · 127 ≤ 2³¹ − 1, so K ≤ 133,144. With UINT8 × INT8: K · 255 · 127, so K ≤ 66,311.

  • Random signs make sums grow like √K, so real overflows are rare.
  • The worst case still matters for correlated data and very large K. Use split-K or blocking.

7.3 Zero-point algebra

Asymmetric activations cost almost nothing:

Σk (qx[t,k] − zx) qw[n,k] = Σk qxqw  −  zx · Σk qw[n,k]
  • The correction Σk qw[n,k] is a per-n constant, precomputed offline.
  • A weight zero-point would require Σk qx[t,k], a runtime row sum per token. That is why weights are symmetric.

7.4 Throughput

  • A100: dense INT8 runs at about 624 TOPS, 2× the 312 TFLOPS of BF16.
  • H100 SXM: INT8 ≈ FP8 ≈ 1979 dense, about 2× BF16 [verify all numbers].
  • Consequence: on Hopper, INT8 buys nothing over FP8, so numerics decide (Lesson 11). Check INT8 support on your target architecture [verify for Blackwell].

7.5 Memory-bound vs compute-bound

  • Decode at small batch is memory-bound: time ≈ weight bytes / bandwidth. W4A16 moves 4× fewer bytes than BF16, W8A8 2× fewer. The weight-only kernel must dequantize in registers efficiently [verify: e.g. Marlin].
  • Prefill and large batches are compute-bound: here W8A8 (or FP8) wins through Tensor Core throughput.

7.6 Tensor parallelism (links to Lesson 7)

  • Column-parallel shards own output channels, so per-channel weight scales shard naturally.
  • Row-parallel shards split K. Per-token activation scales are computed on each shard and differ between ranks. That is legal because each rank dequantizes its partial sums to BF16 before the all-reduce.
  • INT32 partials cannot be all-reduced when their scales differ.
  • Calibrate globally.
    • Per-tensor amax and SmoothQuant factors are per-K statistics. Compute them on the full tensor, or all-reduce the amax with MAX.
    • Slice the result to match the shard layout.
    • Shard-local amax gives results that depend on the TP degree.

7.7 Deployment

  • Explicit quantization: ONNX Q/DQ nodes, consumed by TensorRT.
  • Edge NPUs and DLAs: often INT8-only, with per-tensor activation scales and sometimes power-of-two scales [verify per target]. This is QAT territory, which is relevant for embedded and defense workloads.
  • KV cache quantization: INT8 or FP8 with per-head or per-token scales. It cuts decode memory traffic separately from the weights.

import copy
import math

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)


def sqnr_db(ref, approx):
    """Signal-to-quantization-noise ratio in dB (uses E[ref^2], not Var)."""
    return 10 * math.log10(ref.pow(2).mean().item() / (ref - approx).pow(2).mean().item())


def amax_along(x, dim):
    """amax per index of `dim` (None = per-tensor), keepdim so it broadcasts against x."""
    if dim is None:
        return x.abs().amax()
    dim = dim % x.dim()
    others = [d for d in range(x.dim()) if d != dim]
    return x.abs().amax(dim=others, keepdim=True)


def fq_sym(x, bits=8, dim=None, amax=None):
    """Symmetric fake-quant, restricted range [-qmax, qmax]. Returns (x_hat, q, scale)."""
    qmax = 2 ** (bits - 1) - 1
    amax = amax_along(x, dim) if amax is None else torch.as_tensor(amax, dtype=x.dtype)
    s = amax.clamp(min=1e-12) / qmax
    q = torch.clamp(torch.round(x / s), -qmax, qmax)
    return q * s, q, s


def fq_asym(x, bits=8):
    """Asymmetric (unsigned) per-tensor fake-quant with an integer zero-point."""
    qmax = 2 ** bits - 1
    lo, hi = x.min().clamp(max=0), x.max().clamp(min=0)
    s = (hi - lo).clamp(min=1e-12) / qmax
    z = torch.round(-lo / s)
    q = torch.clamp(torch.round(x / s) + z, 0, qmax)
    return (q - z) * s

def w8a8(ln_mod, lin_mod, h):
    """Per-token dynamic activation quant + per-output-channel weight quant."""
    xq = fq_sym(ln_mod(h), 8, dim=0)[0]
    return F.linear(xq, fq_sym(lin_mod.weight, 8, dim=0)[0], lin_mod.bias)


def smooth(ln_mod, lin_mod, h_calib, alpha):
    """Smoothed copies: X' = X / s (folded into LN gamma/beta), W' = W * s (column-wise)."""
    ln2, lin2 = copy.deepcopy(ln_mod), copy.deepcopy(lin_mod)
    ax = ln_mod(h_calib).abs().amax(0)                 # per input channel, from calibration data
    aw = lin_mod.weight.abs().amax(0)                  # per input channel (column max)
    s = (ax.pow(alpha) / aw.pow(1 - alpha)).clamp(min=1e-5)
    ln2.weight.div_(s)
    ln2.bias.div_(s)
    lin2.weight.mul_(s)                                # broadcasts over rows: W[:, j] *= s_j
    return ln2, lin2

# ---------------- Part 6: STE, LSQ and QAT vs PTQ ----------------
def round_ste(x):
    """Forward: round(x). Backward: identity (straight-through estimator)."""
    return x + (torch.round(x) - x).detach()


def grad_scale(x, g):
    """Forward: x. Backward: gradient multiplied by g (LSQ step-size gradient scaling)."""
    return (x - x * g).detach() + x * g


v = torch.tensor([-5.0, -0.7, 0.2, 1.4, 5.0], requires_grad=True)
s = torch.tensor(0.5, requires_grad=True)
(round_ste(torch.clamp(v / s, -3, 3)) * s).sum().backward()
print("\nSTE dy/dv:", v.grad.tolist())
print(f"LSQ dy/ds: {s.grad.item():.3f}")


class LSQWeight(nn.Module):
    """Learned per-output-channel step size (LSQ), symmetric [-qmax, qmax]."""

    def __init__(self, w, bits):
        super().__init__()
        self.qmax = 2 ** (bits - 1) - 1
        self.s = nn.Parameter(2 * w.abs().mean(1, keepdim=True) / math.sqrt(self.qmax))

    def forward(self, w):
        s = grad_scale(self.s, 1.0 / math.sqrt(w.shape[1] * self.qmax))
        return round_ste(torch.clamp(w / s, -self.qmax, self.qmax)) * s


class QLinear(nn.Module):
    def __init__(self, lin_mod, bits):
        super().__init__()
        self.weight = nn.Parameter(lin_mod.weight.detach().clone())
        self.bias = nn.Parameter(lin_mod.bias.detach().clone())
        self.wq = LSQWeight(self.weight.detach(), bits)

    def forward(self, x):
        return F.linear(x, self.wq(self.weight), self.bias)

9. Interview drills (~15 min)

9.1 Thirty-second answer: "How would you deploy a 7B LLM in INT8?"

"Weights are easy and activations are hard. LLM activations have a few systematic outlier channels, and an INT8 GEMM only allows per-token activation scales and per-output-channel weight scales, because the scales have to factor out of the k-sum. So I'd start with per-channel symmetric weights and dynamic per-token activations, fused into the norm kernel. Then I'd apply SmoothQuant: rescale each input channel by sj = max|Xj|α/max|Wj|1−α, with s folded offline into the norm γ, the V-projection and the up-projection. I'd tune α on a calibration set and run a per-layer sensitivity sweep, keeping the lm_head in BF16 if it's needed. On Hopper, FP8 has the same throughput as INT8, so I'd benchmark FP8 too. For batch-1 decode I'd also consider W4A16, because that regime is memory-bound."

9.2 Whiteboard prompts

Why doesn't per-token activation quantization fix LLM outliers?

The outliers are per-channel: a few fixed k-indices, present in nearly every token. Each token's amax is therefore set by those channels, and per-token scaling changes little. Per-channel X scales would fix it, but they index the reduction dimension, so they can't be factored out of an integer GEMM. They can only be moved into W, which is SmoothQuant.

Derive SmoothQuant and say where the factors go.
  • Start from XWT = (X·diag(s)−1)(W·diag(s))T and choose sj = max|Xj|α/max|Wj|1−α.
  • At α = 0.5, both channel maxima become √(max|Xj|·max|Wj|).
  • Fold 1/s into whatever produces X linearly per channel:
    • norm γ/β for QKV and gate/up (one shared s);
    • V-projection output channels for o_proj (with a GQA group constraint);
    • up-projection output channels for down_proj (never gate, because of the SiLU).
  • Runtime cost: zero.
Your INT8 PTQ model is 5 points worse than FP16. Debug it.
  1. Check that FP32 fake-quant matches the deployed engine. This rules out kernel bugs or a missing epilogue bias.
  2. Run a per-layer sensitivity sweep (quantize one layer at a time) and inspect the output SQNR per layer.
  3. Inspect activation histograms for outlier channels. Fix them with SmoothQuant, or keep the layer in FP16.
  4. Check whether the calibration data is representative, and try percentile or MSE calibration.
  5. In CNNs, check BN folding and per-channel weights, and apply bias correction.
  6. If it is still bad: QAT.
Edge detector on an INT8-only NPU with per-tensor static activations: PTQ or QAT?

Likely QAT.

  • The hardware forbids the escape hatches: no per-token scales, no mixed precision and possibly power-of-two scales.
  • Small CNNs have little redundancy.

Recipe:

  1. Calibrate first. Apply CLE if there are depthwise convs.
  2. Run QAT with fake quantization that matches the target exactly (rounding mode, scale constraints, fused BN).
  3. Use LSQ, then freeze BN and the observers near the end.
Why are weight zero-points avoided in INT8 GEMMs?

An activation zero-point adds −zxΣkqw[n,k], a per-n constant precomputed offline. A weight zero-point adds −zwΣkqx[t,k], a per-token row sum at runtime, plus a cross term. Weights are near-symmetric anyway, so symmetric weight quantization costs almost no accuracy.

Explain STE and the LSQ gradient. Why does training through round() work at all?
  • STE: the forward pass uses the quantized value, and the backward pass treats round as the identity, zeroed outside the clip range. The weights get gradients for the nearby continuous network, and their latent float values cross rounding boundaries when the loss benefits.
  • LSQ: ∂x̂/∂s = round(x/s) − x/s inside the range and ±Q at the clip. That balances rounding error against clipping error, which is §2.3 learned end to end.
  • Caveat: weights can oscillate across boundaries late in training.
