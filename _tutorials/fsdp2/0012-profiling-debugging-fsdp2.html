When things go wrong — and they will — you need systematic tools to identify whether it's memory, communication, compute, or a silent correctness bug.

The Three Failure Modes

Failure modeSymptomTool
OOM (Out of Memory) CUDA OOM error, usually mid-step Memory snapshot, memory timeline
Hang / Deadlock Training freezes, no progress, no error NCCL debug, flight recorder, py-spy
Silent correctness bug Training runs but loss doesn't converge, or converges to wrong value Gradient comparison, numerical verification

This lesson gives you systematic approaches for each, with FSDP2-specific tools and patterns.

Part 1: Memory Profiling

Tool: torch.cuda.memory_stats()

def print_memory_summary(local_rank: int, label: str = "") -> None:
    """Quick memory snapshot. Call at strategic points."""
    stats = torch.cuda.memory_stats(local_rank)

    allocated_gb = stats["allocated_bytes.all.current"] / 1e9
    reserved_gb = stats["reserved_bytes.all.current"] / 1e9
    peak_gb = stats["allocated_bytes.all.peak"] / 1e9

    # Number of allocation retries (indicates fragmentation)
    retries = stats.get("num_alloc_retries", 0)

    print(f"[Rank {local_rank}][{label}] "
          f"Allocated: {allocated_gb:.2f} GB | "
          f"Reserved: {reserved_gb:.2f} GB | "
          f"Peak: {peak_gb:.2f} GB | "
          f"Retries: {retries}")


# Strategic placement in training:
def train_step_instrumented(model, images, labels, optimizer, local_rank):
    print_memory_summary(local_rank, "before_forward")

    outputs = model(images)
    print_memory_summary(local_rank, "after_forward")

    loss = nn.functional.cross_entropy(outputs, labels)
    loss.backward()
    print_memory_summary(local_rank, "after_backward")

    optimizer.step()
    print_memory_summary(local_rank, "after_optimizer")

    optimizer.zero_grad()
    print_memory_summary(local_rank, "after_zero_grad")

    return loss.item()

def capture_memory_snapshot(local_rank: int, output_dir: str = "./memory_snapshots"):
    """
    Capture a detailed memory snapshot showing every allocation.
    View in the PyTorch Memory Visualizer: https://pytorch.org/memory_viz
    """
    import os
    os.makedirs(output_dir, exist_ok=True)

    # Start recording BEFORE the step you want to analyze
    torch.cuda.memory._record_memory_history(
        max_entries=100000,
        context="all",   # Record Python call stacks
    )

    # ... run one training step ...

    # Save snapshot
    snapshot = torch.cuda.memory._snapshot()
    output_path = f"{output_dir}/snapshot_rank{local_rank}.pickle"

    import pickle
    with open(output_path, "wb") as f:
        pickle.dump(snapshot, f)

    # Stop recording
    torch.cuda.memory._record_memory_history(enabled=None)

    print(f"[Rank {local_rank}] Memory snapshot saved to {output_path}")
    print(f"  View at: https://pytorch.org/memory_viz")
    print(f"  Upload the .pickle file to the visualizer")

def train_with_memory_capture(model, dataloader, optimizer, local_rank, capture_step=5):

Diagnosing OOM in FSDP2

# OOM in FSDP2 almost always falls into one of these categories:

# 1. Activation memory overflow (most common)
#    Symptom: OOM occurs during forward pass
#    Cause: batch too large, or forgot activation checkpointing
#    Fix: reduce batch_size or enable model.set_grad_checkpointing(True)

# 2. Peak backward memory
#    Symptom: OOM during backward (after forward succeeded)
#    Cause: recomputed activations (from AC) + gradient accumulation
#    Cause: too many blocks checkpointed into one segment
#    Fix: finer AC granularity, or reduce batch

# 3. Optimizer state allocation (first step only)
#    Symptom: OOM on first optimizer.step()
#    Cause: optimizer allocates exp_avg + exp_avg_sq on first step
#    Fix: ensure optimizer is built AFTER fully_shard(); check shard sizes

# 4. NCCL buffer allocation
#    Symptom: OOM on first collective (before any compute)
#    Cause: NCCL reserves workspace buffers (~200MB-1GB depending on config)
#    Fix: set NCCL_BUFFSIZE to a smaller value, or account for NCCL overhead in budget

# 5. Memory fragmentation
#    Symptom: OOM despite allocated < total GPU memory
#    Diagnostic: check stats["num_alloc_retries"] — if high, fragmentation is the issue
#    Fix: torch.cuda.memory.set_per_process_memory_fraction() or PYTORCH_CUDA_ALLOC_CONF

# Diagnostic flowchart:
def diagnose_oom(local_rank):
    stats = torch.cuda.memory_stats(local_rank)
    allocated = stats["allocated_bytes.all.peak"] / 1e9
    reserved = stats["reserved_bytes.all.peak"] / 1e9
    total = torch.cuda.get_device_properties(local_rank).total_mem / 1e9

    print(f"Peak allocated: {allocated:.2f} GB")
    print(f"Peak reserved:  {reserved:.2f} GB")
    print(f"Total GPU mem:  {total:.2f} GB")
    print(f"Fragmentation gap: {reserved - allocated:.2f} GB")

    if reserved - allocated > 2.0:
        print("⚠️  Significant fragmentation! Consider PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True")

    retries = stats.get("num_alloc_retries", 0)
    if retries > 10:
        print(f"⚠️  {retries} allocation retries — memory allocator struggling")
Fragmentation fix for FSDP2: FSDP2's repeated all-gather (allocate full tensor) → free → all-gather cycle can fragment GPU memory over time. Set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True to enable PyTorch's expandable segments allocator, which dramatically reduces fragmentation for FSDP workloads. This is recommended by default for all FSDP2 training. 
# Add to your Slurm script or shell environment:
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True

Tool: torch.profiler with NCCL Tracing

from torch.profiler import profile, schedule, ProfilerActivity, tensorboard_trace_handler


def profile_training(model, dataloader, optimizer, local_rank, output_dir="./profiles"):
    """
    Profile 5 training steps (after warm-up) with full NCCL visibility.
    """
    os.makedirs(output_dir, exist_ok=True)

    prof_schedule = schedule(
        wait=2,      # Skip steps 0-1 (compilation, prefetch learning)
        warmup=1,    # Step 2: profiler warm-up
        active=5,    # Steps 3-7: record
        repeat=1,
    )

    with profile(
        activities=[ProfilerActivity.CPU, ProfilerActivity.CUDA],
        schedule=prof_schedule,
        on_trace_ready=tensorboard_trace_handler(
            f"{output_dir}/rank{local_rank}"
        ),
        record_shapes=True,
        profile_memory=True,
        with_stack=True,
        # Enable NCCL tracing (PyTorch 2.4+)
        experimental_config=torch._C._profiler._ExperimentalConfig(
            enable_cuda_sync_events=True
        ),
    ) as prof:

        for step, (images, labels) in enumerate(dataloader):
            if step >= 8:
                break

            images = images.to(local_rank, non_blocking=True)
            labels = labels.to(local_rank, non_blocking=True)

            outputs = model(images)
            loss = nn.functional.cross_entropy(outputs, labels)
            loss.backward()
            optimizer.step()
            optimizer.zero_grad()

            prof.step()

    if local_rank == 0:
        # Print summary table
        print(prof.key_averages().table(
            sort_by="cuda_time_total", row_limit=20
        ))

        # NCCL-specific summary
        print("\n--- NCCL Operations ---")
        for evt in prof.key_averages():
            if "nccl" in evt.key.lower():
                print(f"  {evt.key}: count={evt.count}, "
                      f"cuda_time={evt.cuda_time_total/1000:.1f}ms")

Interpreting the Profiler Output

# Key metrics from profiler key_averages():

# 1. Total NCCL time vs total compute time
#    If nccl_total > compute_total → communication-bound
#    If nccl_total < 0.3 × compute_total → good overlap potential

# 2. Individual collective costs:
#    ncclAllGather: should be < 1ms per call on NVLink (for 76 MB blocks)
#    ncclReduceScatter: similar to AllGather
#    ncclAllReduce: gradient sync in HSDP — check if this dominates

# 3. "cudaStreamSynchronize" or "cudaDeviceSynchronize" events:
#    These indicate stalls where the GPU waits for something.
#    If these appear between compute kernels → overlap failure

# 4. CPU-side overhead:
#    Look for long Python operations between CUDA kernel launches.
#    "aten::to" (dtype cast), "aten::copy_" (data transfer) — should be < 0.1ms each
#    If Python overhead is large → torch.compile not active or graph breaks present

Extracting FSDP2-Specific Metrics

def analyze_fsdp2_profile(prof):
    """Extract FSDP2-specific metrics from profiler results."""

    events = prof.key_averages()

    # Separate compute vs communication
    compute_time_us = 0
    comm_time_us = 0
    nccl_events = []

    for evt in events:
        if "nccl" in evt.key.lower():
            comm_time_us += evt.cuda_time_total
            nccl_events.append(evt)
        elif evt.device_type == torch.autograd.DeviceType.CUDA:
            compute_time_us += evt.cuda_time_total

    compute_ms = compute_time_us / 1000
    comm_ms = comm_time_us / 1000

    print(f"\n{'='*50}")
    print(f"FSDP2 Performance Analysis")
    print(f"{'='*50}")
    print(f"Total compute time: {compute_ms:.1f} ms")
    print(f"Total NCCL time:    {comm_ms:.1f} ms")
    print(f"Compute/Comm ratio: {compute_ms/max(comm_ms, 0.01):.1f}×")

    if compute_ms / max(comm_ms, 0.01) > 3:
        print("✓ Good overlap potential (ratio > 3×)")
    else:
        print("⚠️ Communication may be exposed (ratio < 3×)")

    print(f"\nNCCL breakdown:")
    for evt in sorted(nccl_events, key=lambda e: -e.cuda_time_total):
        avg_ms = evt.cuda_time / evt.count / 1000
        print(f"  {evt.key}: {evt.count}× calls, "
              f"total={evt.cuda_time_total/1000:.1f}ms, "
              f"avg={avg_ms:.2f}ms/call")

    # Estimate overlap efficiency
    # If compute + comm > measured step time → some overlap occurred
    # overlap_fraction ≈ 1 - (step_time - compute_time) / comm_time

    return {
        "compute_ms": compute_ms,
        "comm_ms": comm_ms,
        "ratio": compute_ms / max(comm_ms, 0.01),
    }

Part 3: Debugging Hangs / Deadlocks

NCCL hangs are the most frustrating FSDP2 failure mode. The training freezes with no error message. Causes:

CauseSymptomDiagnosisFix
Rank divergence (different code paths) Some ranks call collective, others don't NCCL timeout error (after NCCL_TIMEOUT) Ensure all ranks execute same control flow
Uneven batch (last batch smaller) Some ranks finish dataloader, others still have data Happens at epoch end without drop_last=True Always use drop_last=True with FSDP2
Exception on one rank One rank crashes, others hang waiting for it Check stderr/logs across ALL ranks Wrap in try/except, broadcast error to all ranks
Network issue (IB flap) Intermittent hangs, especially cross-node NCCL debug shows timeout after healthy communication Check IB health: ibstat, network monitoring
CUDA error on one rank One rank hits illegal memory access, others hang Set CUDA_LAUNCH_BLOCKING=1 to get exact failure location Fix the CUDA error; the hang is a consequence

Part 4: Debugging Correctness Issues

Gradient Comparison: FSDP2 vs Single-GPU

def verify_fsdp2_gradients(
    model_fsdp: nn.Module,
    model_reference: nn.Module,
    sample_input: torch.Tensor,
    sample_target: torch.Tensor,
    local_rank: int,
) -> None:
    """
    Compare FSDP2 gradients to a single-GPU reference model.
    The reference model should be the same architecture with same weights.

    Call on rank 0 only (reference model on rank 0's GPU).
    """
    from torch.distributed.checkpoint.state_dict import get_model_state_dict, StateDictOptions

    # Get full state dict from FSDP2 model
    options = StateDictOptions(full_state_dict=True, cpu_offload=True)
    fsdp_state = get_model_state_dict(model_fsdp, options=options)

    if local_rank == 0:
        # Load into reference model
        model_reference.load_state_dict(fsdp_state)
        model_reference = model_reference.cuda()

        # Forward + backward on reference (single GPU, no sharding)
        ref_out = model_reference(sample_input)
        ref_loss = nn.functional.cross_entropy(ref_out, sample_target)
        ref_loss.backward()

        ref_grads = {
            name: p.grad.clone()
            for name, p in model_reference.named_parameters()
            if p.grad is not None
        }

    # Forward + backward on FSDP2 model (distributed)
    fsdp_out = model_fsdp(sample_input)
    fsdp_loss = nn.functional.cross_entropy(fsdp_out, sample_target)
    fsdp_loss.backward()

    # Gather FSDP2 gradients to rank 0 for comparison
    # (Only works for parameters where we can access full grad)
    if local_rank == 0:
        # Get full gradients from FSDP2 (requires gathering)
        fsdp_full_grads = {}
        for name, p in model_fsdp.named_parameters():
            if p.grad is not None:
                # For DTensor grads: gather full tensor
                if hasattr(p.grad, 'full_tensor'):
                    fsdp_full_grads[name] = p.grad.full_tensor()
                else:
                    fsdp_full_grads[name] = p.grad.clone()

        # Compare
        print("\nGradient comparison (FSDP2 vs reference):")
        max_diff = 0.0
        for name in ref_grads:
            if name in fsdp_full_grads:
                diff = (ref_grads[name] - fsdp_full_grads[name]).abs().max().item()
                rel_diff = diff / max(ref_grads[name].abs().max().item(), 1e-8)
                max_diff = max(max_diff, rel_diff)
                if rel_diff > 1e-4:
                    print(f"  ⚠️  {name}: rel_diff={rel_diff:.2e}")

        if max_diff < 1e-4:
            print(f"  ✓ All gradients match (max rel_diff={max_diff:.2e})")
        else:
            print(f"  ⚠️  Max relative difference: {max_diff:.2e}")

    model_fsdp.zero_grad()

Common Correctness Bugs

# Bug 1: Forgetting dataloader.sampler.set_epoch(epoch)
# Symptom: Training converges but worse than expected
# Cause: Without set_epoch(), same random seed every epoch → same data order
#         Model memorizes the order, not the data
# Fix: Always call sampler.set_epoch(epoch)

# Bug 2: Different random seeds across ranks
# Symptom: Slightly different results vs single-GPU (beyond fp precision)
# Cause: Operations like dropout use per-rank RNG → different masks on each rank
#         For FSDP2 this is EXPECTED (each rank processes different data)
# Non-issue: As long as the gradient reduction is correct, this is fine

# Bug 3: grad_norm clipping with wrong world_size assumption
# Symptom: Training diverges with FSDP2 but works with DDP
# Cause: Manual grad norm calculation that doesn't account for sharded grads
# Fix: Always use torch.nn.utils.clip_grad_norm_ which handles DTensor correctly

# Bug 4: Learning rate not scaled for effective batch size
# Symptom: Training converges but to suboptimal loss
# Cause: Effective batch = per_gpu_batch × world_size (in FSDP, same as DDP)
#         If you used lr=1e-4 for batch=32, you might need lr=4e-4 for batch=128
# Fix: Apply linear scaling rule or use per-sample LR

# Bug 5: Mixed precision masking NaN/Inf before they propagate
# Symptom: Loss doesn't converge, stays flat or oscillates
# Cause: fp16 overflow produces NaN in attention, which gets masked by softmax
#         downstream layers see all-zeros instead of meaningful gradients
# Fix: Check for NaN after each block during debugging:

def check_nan_hook(module, input, output):
    if isinstance(output, torch.Tensor):
        if torch.isnan(output).any():
            print(f"⚠️ NaN detected in {module.__class__.__name__}")
            raise RuntimeError(f"NaN in {module.__class__.__name__}")
    elif isinstance(output, tuple):
        for i, o in enumerate(output):
            if isinstance(o, torch.Tensor) and torch.isnan(o).any():
                print(f"⚠️ NaN detected in {module.__class__.__name__} output[{i}]")
                raise RuntimeError(f"NaN in {module.__class__.__name__}")

# Register on all modules:
for name, module in model.named_modules():
    module.register_forward_hook(check_nan_hook)

Part 5: Comprehensive Debugging Toolkit

"""
fsdp2_debug.py — Reusable debugging utilities for FSDP2 training.
Import and activate selectively during debugging sessions.
"""
import os
import time
import torch
import torch.distributed as dist
from typing import Optional


class FSDP2Debugger:
    """
    Comprehensive debugging for FSDP2 training.
    Activate selectively — all checks have performance cost.
    """

    def __init__(self, local_rank: int, enabled: bool = True):
        self.local_rank = local_rank
        self.enabled = enabled
        self.step_count = 0
        self.step_times = []
        self.memory_history = []

    def step_start(self) -> None:
        """Call at beginning of each training step."""
        if not self.enabled:
            return
        torch.cuda.synchronize()
        self._step_start_time = time.perf_counter()
        self.memory_history.append({
            "step": self.step_count,
            "before": torch.cuda.memory_allocated(self.local_rank) / 1e9,
        })

    def step_end(self) -> None:
        """Call at end of each training step."""
        if not self.enabled:
            return
        torch.cuda.synchronize()
        elapsed = time.perf_counter() - self._step_start_time
        self.step_times.append(elapsed)
        self.memory_history[-1]["after"] = torch.cuda.memory_allocated(self.local_rank) / 1e9
        self.memory_history[-1]["peak"] = torch.cuda.max_memory_allocated(self.local_rank) / 1e9
        self.step_count += 1

    def check_gradients(self, model: torch.nn.Module) -> dict:
        """Check gradient health after backward."""
        if not self.enabled:
            return {}

        results = {"zero_pct": [], "has_nan": False, "has_inf": False, "norms": []}

        for name, param in model.named_parameters():
            if param.grad is None:
                continue

            grad = param.grad
            if hasattr(grad, '_local_tensor'):
                grad = grad._local_tensor

            # Check for pathological values
            if torch.isnan(grad).any():
                results["has_nan"] = True
                if self.local_rank == 0:
                    print(f"  ⚠️ NaN gradient: {name}")

            if torch.isinf(grad).any():
                results["has_inf"] = True
                if self.local_rank == 0:
                    print(f"  ⚠️ Inf gradient: {name}")

            # Check for underflow (many zeros)
            zero_pct = (grad == 0).float().mean().item() * 100
            results["zero_pct"].append((name, zero_pct))

            # Gradient norm
            norm = grad.norm().item()
            results["norms"].append((name, norm))

        # Report suspicious patterns
        if self.local_rank == 0 and self.step_count % 50 == 0:
            worst_zeros = sorted(results["zero_pct"], key=lambda x: -x[1])[:3]
            for name, pct in worst_zeros:
                if pct > 30:
                    print(f"  ⚠️ {name}: {pct:.1f}% zero gradients")

        return results

    def check_weight_update(self, model: torch.nn.Module) -> None:
        """Verify parameters actually changed after optimizer step."""
        if not self.enabled:
            return

        if not hasattr(self, '_prev_params'):
            # First call: store current params
            self._prev_params = {}
            for name, p in model.named_parameters():
                local = p._local_tensor if hasattr(p, '_local_tensor') else p
                self._prev_params[name] = local.detach().clone()
            return

        unchanged = []
        for name, p in model.named_parameters():
            local = p._local_tensor if hasattr(p, '_local_tensor') else p
            if name in self._prev_params:
                diff = (local - self._prev_params[name]).abs().max().item()
                if diff == 0:
                    unchanged.append(name)
                # Update stored params
                self._prev_params[name] = local.detach().clone()

        if unchanged and self.local_rank == 0:
            print(f"  ⚠️ {len(unchanged)} parameters unchanged after optimizer step!")
            for name in unchanged[:5]:
                print(f"    - {name}")

    def check_all_ranks_synchronized(self) -> None:
        """
        Verify all ranks are at the same point.
        Call before critical collective operations to prevent hangs.
        """
        if not self.enabled:
            return

        # Use barrier with timeout
        try:
            work = dist.barrier(async_op=True)
            work.wait(timeout=30.0)  # 30 second timeout
        except RuntimeError:
            print(f"  ⚠️ Rank {self.local_rank} timed out at barrier! "
                  f"Other ranks may have diverged.")
            raise

    def report(self) -> None:
        """Print summary after training."""
        if not self.enabled or self.local_rank != 0:
            return

        if len(self.step_times) < 3:
            return

        # Skip first 2 steps (warm-up)
        steady = self.step_times[2:]
        avg = sum(steady) / len(steady)
        std = (sum((t-avg)**2 for t in steady) / len(steady)) ** 0.5

        print(f"\n{'='*50}")
        print(f"FSDP2 Debug Report ({len(steady)} steady-state steps)")
        print(f"{'='*50}")
        print(f"Step time: {avg*1000:.1f} ± {std*1000:.1f} ms")

        # Check for step time outliers (possible stragglers)
        outliers = [i for i, t in enumerate(steady) if t > avg + 3*std]
        if outliers:
            print(f"⚠️ Step time outliers at indices: {outliers}")

        # Memory
        if self.memory_history:
            peaks = [m["peak"] for m in self.memory_history if "peak" in m]
            print(f"Peak memory: {max(peaks):.2f} GB")
            print(f"Memory range: {min(peaks):.2f} – {max(peaks):.2f} GB")

            # Check for memory leak (steadily increasing)
            if len(peaks) > 10:
                first_half_avg = sum(peaks[:len(peaks)//2]) / (len(peaks)//2)
                second_half_avg = sum(peaks[len(peaks)//2:]) / (len(peaks) - len(peaks)//2)
                if second_half_avg > first_half_avg * 1.05:
                    print(f"⚠️ Possible memory leak: "
                          f"first half avg={first_half_avg:.2f} GB, "
                          f"second half avg={second_half_avg:.2f} GB")

fsdp2_healthcheck.py — Run this to validate your FSDP2 setup before long training.
Launch: torchrun --nproc_per_node=4 fsdp2_healthcheck.py

import os

import torch.nn as nn

from torch.distributed.device_mesh import init_device_mesh


def main():

    local_rank = int(os.environ["LOCAL_RANK"])
    world_size = dist.get_world_size()
    torch.cuda.set_device(local_rank)

    rank = dist.get_rank()
    checks_passed = 0
    checks_total = 0

    def check(name: str, condition: bool, detail: str = ""):
        nonlocal checks_passed, checks_total
        checks_total += 1
        status = "✓" if condition else "✗"
        if rank == 0:
            msg = f"  [{status}] {name}"
            if detail:
                msg += f" — {detail}"
            print(msg)
        if condition:
            checks_passed += 1
        return condition

    if rank == 0:
        print(f"\n{'='*60}")
        print(f"  FSDP2 Health Check")
        print(f"{'='*60}\n")

    # --- Environment ---
    if rank == 0:
        print("Environment:")

    check("PyTorch version >= 2.4",
          tuple(int(x) for x in torch.__version__.split('.')[:2]) >= (2, 4),
          f"Found: {torch.__version__}")

    check("CUDA available", torch.cuda.is_available())

    check("NCCL backend", dist.get_backend() == "nccl")

    check("expandable_segments enabled",
          "expandable_segments" in os.environ.get("PYTORCH_CUDA_ALLOC_CONF", ""),
          "Set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True")

    # --- GPU Topology ---
    if rank == 0:
        print("\nGPU Topology:")

    gpu_name = torch.cuda.get_device_name(local_rank)
    gpu_mem = torch.cuda.get_device_properties(local_rank).total_mem / 1e9
    check(f"GPU: {gpu_name}", True, f"{gpu_mem:.0f} GB")

    local_world = int(os.environ.get("LOCAL_WORLD_SIZE", torch.cuda.device_count()))
    num_nodes = world_size // local_world
    check(f"Topology: {num_nodes} nodes × {local_world} GPUs/node", True)

    # --- NCCL Communication ---
    if rank == 0:
        print("\nNCCL Communication:")

    # Test all-reduce
    test_tensor = torch.ones(1000, device=f"cuda:{local_rank}") * rank
    dist.all_reduce(test_tensor)
    expected_sum = sum(range(world_size)) * 1000
    check("All-reduce works",
          abs(test_tensor.sum().item() - expected_sum) < 1e-3)

    # Test all-gather bandwidth
    size_mb = 64  # 64 MB test
    data = torch.randn(size_mb * 1024 * 1024 // 4, device=f"cuda:{local_rank}")
    gathered = [torch.empty_like(data) for _ in range(world_size)]

    torch.cuda.synchronize()
    dist.barrier()
    start = torch.cuda.Event(enable_timing=True)
    end = torch.cuda.Event(enable_timing=True)

    start.record()
    dist.all_gather(gathered, data)
    end.record()
    torch.cuda.synchronize()

    elapsed_ms = start.elapsed_time(end)
    bandwidth_gbps = (size_mb * world_size / 1000) / (elapsed_ms / 1000)
    check(f"All-gather bandwidth", bandwidth_gbps > 10,
          f"{bandwidth_gbps:.1f} GB/s for {size_mb}MB × {world_size} ranks")

    # --- FSDP2 Basic Functionality ---
    if rank == 0:
        print("\nFSDP2 Functionality:")

    # Create a small test model
    test_model = nn.Sequential(
        nn.Linear(256, 512), nn.ReLU(), nn.Linear(512, 256)
    )

    mesh = init_device_mesh("cuda", (world_size,))
    mp_policy = MixedPrecisionPolicy(param_dtype=torch.float16, reduce_dtype=torch.float32)

    # Check DTensor creation
    first_param = next(test_model.parameters())
    check("Parameters are DTensor",
          "DTensor" in type(first_param).__name__)
    check("Placement is Shard(0)",
          str(first_param.placements) == "(Shard(dim=0),)")

    test_output = test_model(test_input)
    test_loss = test_output.sum()
    test_loss.backward()

    check("Forward pass works", test_output.shape == (8, 256))
    check("Backward pass works",
          all(p.grad is not None for p in test_model.parameters()))

    opt = torch.optim.AdamW(test_model.parameters(), lr=1e-3)
    opt.step()
    check("Optimizer step works", True)

          remaining > 5.0,

        print(f"{'='*60}\n")

Check Your Understanding

Q1: Your FSDP2 training OOMs at step 50 (not step 0). Memory snapshot shows peak_allocated is 30.5 GB on a 32 GB V100. What's the most useful diagnostic?

Correct. OOM at step 50 (not step 0) suggests something is growing over time — a memory leak. The memory timeline visualization shows exactly WHICH tensors are accumulating. Common causes: gradients not being freed (optimizer.zero_grad() missing), intermediate tensors retained by Python references, or a logging utility that stores tensor history. Reducing batch size (A) is a band-aid. NCCL buffers (C) don't grow over time. Expandable segments (D) helps fragmentation but not genuine leaks.

Q2: Training hangs after 200 steps. No error message. NCCL_DEBUG=INFO shows the last completed collective was "ncclReduceScatter" for block 15 on all ranks. What's the likely issue?

Correct. If reduce-scatter for block 15 completed (all ranks participated), the next expected operation is block 14's pre-backward all-gather (backward goes 31→0). If that all-gather is hanging, one rank isn't contributing its shard. Most likely: that rank encountered a CUDA error during block 16's activation recomputation (part of checkpointing), which killed its NCCL communicator. The other ranks wait indefinitely for its all-gather data. Fix: set CUDA_LAUNCH_BLOCKING=1 and check that rank's stderr for the underlying CUDA error.

Q3: You set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True for your FSDP2 training. What specific problem does this solve?

Correct. FSDP2 repeatedly allocates large buffers (full parameter during all-gather) and frees them (post-forward/post-backward). The default CUDA allocator can leave "holes" in memory (fragmentation) where freed blocks aren't contiguous with neighboring free blocks. Expandable segments allows the allocator to manage memory in flexible segments that can grow, avoiding the situation where allocated=20GB but reserved=30GB (10GB fragmented/unusable). This is the PyTorch team's recommended setting for all FSDP workloads.

Q4: Your FSDP2 training shows 50% zero gradients for early layers after 1000 steps. reduce_dtype is fp32. What's wrong?

Correct. 50% zero gradients in early layers is a vanishing gradient problem — a training/architecture issue, not an FSDP2 bug. With reduce_dtype=fp32, there's no underflow from the sharding/communication pipeline. To confirm: run the same model with DDP (no sharding) and check if the same pattern appears. If yes, the fix is architectural: better initialization (e.g., scaled init), reduce weight decay, add gradient clipping, or use residual connections more aggressively. FSDP2 should produce identical gradients to DDP (up to fp precision).

Key Takeaways

  1. Always set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True for FSDP2 training. This is the single most impactful environment variable for preventing OOM from fragmentation.
  2. Memory snapshot + pytorch.org/memory_viz is the definitive OOM debugging tool. It shows every allocation with call stacks.
  3. For hangs: NCCL_DEBUG=INFO + NCCL_TIMEOUT=120 + py-spy. Check drop_last=True and that all ranks execute the same control flow.
  4. For correctness: Compare gradients to a single-GPU reference. Check for fp16 overflow (NaN), underflow (excess zeros), and data pipeline bugs (sampler.set_epoch).
  5. torch.profiler → TensorBoard for performance profiling. Extract compute-to-comm ratio and identify exposed communication tails.
  6. Health check script before long runs. Validates topology, NCCL bandwidth, FSDP2 basic functionality, and memory budget in 30 seconds.
  7. First rule of debugging: check ALL ranks' output. The error is often on a non-zero rank whose stderr you're not watching.
