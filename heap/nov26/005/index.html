Lesson 005

Lesson 5: FP8 Training

Interview skill: Design and defend an FP8 training recipe: format per tensor, scale computation, what stays in higher precision, and how it fails.

Legend: verified = checked against the primary source in this session · verify = from memory; check before quoting in an interview.

1. Why FP8, and the core problem

  • Throughput: On Hopper/Ada, dense FP8 Tensor Core throughput is about 2× BF16 verify (NVIDIA spec sheets).
  • Bandwidth and memory: FP8 uses half the bytes of BF16 for GEMM inputs and for activations saved for backward.
  • The catch: The dynamic range is tiny. Count it in binades, log2(max / min subnormal):
FormatMaxMin subnormalBinades (log2 ratio)eps
BF16≈3.39e382−133≈2612−7
FP16655042−24≈402−10
FP8 E5M257344 = 1.75·2152−16≈31.82−2
FP8 E4M3448 = 1.75·282−9≈17.82−3

Consequence: FP16 got away with one global loss scale because 40 binades cover most tensors once they are shifted. E4M3's ~18 binades (~15 counting normals only) cannot cover activations, weights and gradients that differ by many orders of magnitude. So FP8 needs a separate scale for each tensor (or each block). That one sentence is the key idea of FP8 training.

2. Two encodings, two roles

E4M3E5M2
Special valuesNo Inf; only S.1111.111 is NaN, so the top exponent is usable verifyIEEE-like: Inf and NaN exist verify
StrengthPrecision (3 mantissa bits)Range (5 exponent bits, same as FP16)
Recommended useWeights and activations (forward)Gradients (backward)

The recommendation in the last row is stated directly in Micikevicius et al. 2022: "The recommended use of FP8 encodings is E4M3 for weight and activation tensors, and E5M2 for gradient tensors." verified (arXiv:2209.05433). Transformer Engine calls this E4M3-forward / E5M2-backward split the HYBRID format verify.

Why gradients get E5M2: Gradient magnitudes vary more across tokens, layers and steps, and they shift over the course of training. Range matters more than the extra mantissa bit there. Forward tensors are better behaved, so precision wins.

3. Scaling math

quantize:    x_q = cast_fp8( clamp(x * s, -FMAX, FMAX) )
scale:       s   = (FMAX / amax) / 2^margin          # FMAX = 448 (E4M3) or 57344 (E5M2)
dequantize:  x  ~= x_q / s
FP8 GEMM:    C   = (A_q @ B_q) / (s_A * s_B)          # FP8 inputs, higher-precision accumulate,
                                                      # 1/(s_A s_B) applied in the GEMM epilogue

Worked example (E4M3, amax = 3.5, margin 0): s = 448 / 3.5 = 128 = 27.

  • Without a scale: x = 0.001 lies below the min normal (2−6), so it lands on the subnormal grid with step 2−9 ≈ 0.00195. 0.001 / 0.00195 = 0.51, which rounds to 1 step = 0.00195. That is a 95% error.
  • With s = 128: 0.128 lies in [2−3, 2−2), where the ulp is 2−6. 0.128 / 2−6 = 8.19, which rounds to 8, giving 0.125. Dividing by 128 gives 0.000977, a 2.3% error.

Tip: If you pick power-of-two scales, multiplying by the scale only shifts the exponent and adds no rounding error of its own. MX formats require power-of-two scales (E8M0); see L6.

4. Scaling strategies

StrategyHow amax is obtainedProCon
Current (just-in-time) per-tensorReduce over the tensor now, then castAccurate and reacts immediately to spikesNeeds an extra pass over the tensor (read, reduce, then cast), and the cast is harder to fuse into the producing kernel
Delayed per-tensor (Transformer Engine's classic default)Max over an amax history from previous iterations; the current amax is recorded for laterThe cast can be fused into the producer kernel, with no extra readStale: a sudden outlier saturates in the current step
Fine-grained block/tileOne scale per tile, e.g. 1×128 for activations and 128×128 for weights (DeepSeek-V3) verifyOutliers only affect their own blockMore scale metadata; the GEMM must apply scales per block
MXFP8 (Blackwell)One E8M0 scale per 32 elements, in hardware verifyHardware-native block scalingCovered in L6

Delayed scaling settings: amax_history_len, amax_compute_algo ("max" or "most_recent"), and margin. Margin gives 2margin of headroom at the cost of precision. With data or tensor parallelism, amaxes are typically all-reduced so that ranks use the same scales verify (TE docs).

# Transformer Engine sketch; the API changes between versions, so check your installed version
import transformer_engine.pytorch as te
from transformer_engine.common.recipe import DelayedScaling, Format

recipe = DelayedScaling(fp8_format=Format.HYBRID, amax_history_len=16, amax_compute_algo="max")
layer  = te.Linear(4096, 4096).cuda()
with te.fp8_autocast(enabled=True, fp8_recipe=recipe):
    y = layer(x)

5. What stays in higher precision, and the memory reality

  • FP8 is used only for GEMM inputs in Linear layers (QKV, out-proj, MLP). Softmax, norms, residual adds, loss, optimizer, and often attention BMMs, embeddings and the LM head stay BF16/FP32. The reasons are the same as in L1 and L3: reductions and exponentials.
  • Accumulation: FP8 GEMMs accumulate in higher precision. DeepSeek-V3 reports that H100 FP8 accumulation keeps only about 14 bits, so they move partial sums to FP32 on CUDA cores every 128 elements along K verify. This is a good systems detail to bring up.
  • Master weights and optimizer state stay FP32/BF16. FP8 adds extra cached FP8 weight copies, plus transposed copies for backward, because Hopper FP8 GEMMs need a specific layout verify. FP8 does not shrink parameter or optimizer memory. It saves GEMM time, bandwidth and saved-activation memory.

6. Failure modes and a debugging checklist

SymptomLikely causeCheck or fix

Diverges only after a long run (many tokens); BF16 is fineActivation outliers grow over training (e.g. SwiGLU amplification), beyond per-tensor range (Fishman et al. 2024, Smooth-SwiGLU) verifyPer-channel/block scaling, or keep that GEMM in BF16
Gradients are mostly zero in some layersUnderflow: scale too small, or the history is dominated by an old spikeCompare amax with history max; look for subnormal/zero fractions

Methodology: Always A/B against a BF16 baseline with identical seeds and data. Bisect by switching FP8 off layer by layer: first and last blocks first, then the MLP versus the attention projections.

7. Interview answer (~30 s)

"FP8 doubles Tensor Core throughput over BF16, but E4M3 covers only about 18 binades, so one global loss scale like in FP16 isn't enough. You need a scale per tensor or per block. We use E4M3 forward for precision and E5M2 for gradients for range. Each tensor is scaled by FMAX over amax, and the GEMM applies the inverse scales in its epilogue with higher-precision accumulation. Delayed scaling takes amax from a history so the cast can be fused, but it lags behind outliers. Current or block scaling fixes that at some cost. Norms, softmax, the optimizer and master weights stay in high precision. So FP8 saves compute and bandwidth, not optimizer memory."

8. Lab (~15 min, CPU is fine, PyTorch ≥ 2.1)

import torch
torch.manual_seed(0)
E4M3, E5M2 = torch.float8_e4m3fn, torch.float8_e5m2
FMAX = {E4M3: 448.0, E5M2: 57344.0}

def q(x, dt, scale=1.0):
    """Quantize-dequantize with a saturating cast."""
    y = (x * scale).clamp(-FMAX[dt], FMAX[dt]).to(dt)
    return y.float() / scale

def rel_err(x, xh):
    return ((x - xh).norm() / x.norm()).item()

# 1) Small-magnitude tensor (like activation gradients)
g = torch.randn(4096) * 1e-5
print("E4M3 no scale        :", rel_err(g, q(g, E4M3)))
print("E5M2 no scale        :", rel_err(g, q(g, E5M2)))
s = FMAX[E4M3] / g.abs().max()
print("E4M3 per-tensor scale:", rel_err(g, q(g, E4M3, s)))

# 2) PREDICT FIRST: what does an UNclamped overflow give in your PyTorch version?
print(torch.tensor([500.0, -1000.0]).to(E4M3).float())

# 3) Delayed scaling hit by an outlier spike
hist, H, margin = [], 16, 0
for step in range(48):
    x = torch.randn(4096)
    if step == 30:
        x[0] = 50.0                                   # outlier
    amax_now = x.abs().max().item()
    scale = (FMAX[E4M3] / max(hist) / 2**margin) if hist else 1.0
    sat = ((x * scale).abs() > FMAX[E4M3]).sum().item()
    err = rel_err(x, q(x, E4M3, scale))
    hist = (hist + [amax_now])[-H:]
    if step in (0, 1, 29, 30, 31, 46, 47):
        print(f"step {step:2d}  scale={scale:7.2f}  saturated={sat}  rel_err={err:.4f}")
