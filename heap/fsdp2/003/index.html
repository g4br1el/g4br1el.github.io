Lesson 003 Core Code

Hands-On: Your First FSDP2 Training Loop

A complete, runnable script that trains ViT-Huge on your V100 cluster using FSDP2. Every line justified.

What We're Building

A single-file training script that:

  • Trains ViT-Huge/14 (632M params) — impossible with DDP on V100-32GB at batch_size > 1
  • Uses FSDP2 (fully_shard) with per-block sharding
  • Uses fp16 mixed precision (V100 — no bf16 hardware support)
  • Runs on multi-GPU single-node first (4× V100, NVLink)
  • Uses torchrun for elastic launch

We'll build it incrementally, explaining each section. The full script is at the end.

Section 1: Imports and Environment

"""
FSDP2 Training: ViT-Huge/14 on V100-32GB cluster.
Launch: torchrun --nproc_per_node=4 train_fsdp2.py
"""
import os
import time
from typing import Optional

import torch
import torch.nn as nn
from torch.utils.data import DataLoader, DistributedSampler

# FSDP2 imports — note the path: _composable, not the old fsdp module
from torch.distributed._composable.fsdp import fully_shard, MixedPrecisionPolicy
from torch.distributed.device_mesh import init_device_mesh

# Standard distributed init
import torch.distributed as dist
from torch.distributed import init_process_group, destroy_process_group

# We'll use timm for ViT-Huge (battle-tested, no need to reimplement)
import timm
Import paths matter. FSDP2 lives under torch.distributed._composable.fsdp (note the underscore — still technically "private" API as of PyTorch 2.4/2.5, but it's the endorsed path forward and used in torchtitan). Do NOT import from torch.distributed.fsdp — that's FSDP1.

Section 2: Distributed Setup

def setup_distributed() -> tuple[int, int]:
    """Initialize distributed process group. Returns (local_rank, world_size)."""
    # torchrun sets these environment variables automatically
    init_process_group(backend="nccl")

    local_rank = int(os.environ["LOCAL_RANK"])
    world_size = dist.get_world_size()

    torch.cuda.set_device(local_rank)

    return local_rank, world_size


def cleanup_distributed() -> None:
    destroy_process_group()

Nothing FSDP-specific here — identical to what you'd do for DDP. The process group provides the NCCL communicator that FSDP2 will use internally.

Section 3: Model Construction

def build_model() -> nn.Module:
    """
    Build ViT-Huge/14 on CPU (NOT on GPU yet).

    Critical: Model must be constructed on CPU or meta device,
    then sharded BEFORE moving to GPU. If you move to GPU first,
    you defeat the purpose — the full model momentarily lives on one GPU.
    """
    # timm's vit_huge_patch14_224: 632M params
    model = timm.create_model(
        "vit_huge_patch14_224",
        pretrained=False,
        num_classes=1000,  # ImageNet-1K for demonstration
    )

    # Verify param count
    total_params = sum(p.numel() for p in model.parameters())
    assert 600_000_000 < total_params < 700_000_000, f"Unexpected: {total_params}"

    return model
Critical pattern: build on CPU, shard, then it materializes on GPU. If you call model.cuda() before fully_shard(), the full 2.4 GB (fp32) model lands on one GPU momentarily. With FSDP2, fully_shard() handles the distribution to GPU. For models that don't fit on a single GPU at all, you'd use meta device initialization + param_init_fn — we'll cover that in a later lesson.

For ViT-Huge (632M × 4 bytes = 2.4 GB fp32), it fits on CPU RAM trivially and on a V100-32GB individually. The problem is activations + optimizer states in DDP. So the CPU-init → shard pattern works cleanly here.

Section 4: Applying FSDP2

This is the core of the lesson. We apply fully_shard() at two levels:

def apply_fsdp2(
    model: nn.Module,
    mesh: "DeviceMesh",
    mp_policy: MixedPrecisionPolicy,
) -> nn.Module:
    """
    Apply FSDP2 sharding to the model.

    Strategy: one FSDP unit per transformer block + one for the root.
    This means during forward/backward, only ONE block's parameters
    are unsharded at a time (~20M params = ~38 MB in fp16).
    """
    # Shard each transformer block individually
    # In timm's ViT, blocks are at model.blocks[i]
    for block_idx, block in enumerate(model.blocks):
        # fully_shard mutates the block in-place
        # After this call:
        #   - block's parameters are DTensors with Shard(0) placement
        #   - pre-forward/post-forward hooks are registered
        #   - block is an FSDP unit
        fully_shard(block, mesh=mesh, mp_policy=mp_policy)

    # Shard the root module (handles patch embedding, cls_token, pos_embed, head)
    # This MUST come after sharding child modules
    fully_shard(model, mesh=mesh, mp_policy=mp_policy)

    return model
Order matters: children first, root last. When you call fully_shard(model) on the root, it only shards parameters that are directly owned by that module (not already in a child FSDP unit). If you shard root first, it would try to shard everything into one unit — defeating per-block granularity.

Why this granularity?

ViT-Huge has 32 transformer blocks, each ~20M parameters:

  • One block unsharded (fp16) ≈ 20M × 2 bytes = 38 MB
  • Root parameters (patch_embed + pos_embed + head) ≈ 2M params = ~4 MB fp16
  • Peak memory from unsharding: ~38 MB — negligible vs. the 32 GB budget

Section 5: Mixed Precision Policy

def get_mixed_precision_policy() -> MixedPrecisionPolicy:
    """
    V100-specific: use fp16 for compute, fp32 for parameter master copies.

    FSDP2's MixedPrecisionPolicy controls:
      - param_dtype: dtype of all-gathered params during forward/backward
      - reduce_dtype: dtype used for gradient reduce-scatter
      - output_dtype: dtype of module outputs (for inter-module communication)
    """
    return MixedPrecisionPolicy(
        param_dtype=torch.float16,    # All-gathered params cast to fp16 for compute
        reduce_dtype=torch.float32,   # Reduce-scatter in fp32 to avoid grad underflow
    )
V100 fp16 pitfall: Unlike A100/H100 with bf16 (which has the same exponent range as fp32), fp16 has a narrow dynamic range. Gradient reduce-scatter in fp16 can underflow for small gradients. Using reduce_dtype=torch.float32 is the safe choice on V100. This means reduce-scatter moves 4 bytes/param instead of 2, but it's a ~25% communication overhead on one of three collectives — acceptable for correctness.

How MixedPrecisionPolicy interacts with the lifecycle

Parameter lifecycle WITH mixed precision: ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ At rest: param is DTensor, Shard(0), stored in fp32 (master weight) local shape: [dim/N, ...] Pre-forward hook: 1. all-gather → full param (still fp32 at this point) 2. cast to param_dtype (fp16) → this is what forward() sees → Memory: full fp16 param exists transiently Forward compute: uses fp16 param → fp16 activations Post-forward hook: → free the full fp16 param buffer Pre-backward hook: 1. all-gather → full fp32 param 2. cast to fp16 → backward uses fp16 Backward compute: produces fp16 gradients Post-backward hook: 1. cast grad to reduce_dtype (fp32) if needed 2. reduce-scatter in fp32 → each rank gets sharded fp32 grad → This fp32 sharded grad is used directly by AdamW on the fp32 master weights
No GradScaler needed! Unlike DDP + AMP where you manually use torch.cuda.amp.GradScaler, FSDP2's mixed precision policy handles the dtype transitions internally. The optimizer always sees fp32 gradients (because reduce_dtype=torch.float32), so no loss scaling is required. This is a significant simplification over DDP + manual AMP.

Section 6: Data Pipeline

def build_dataloader(
    world_size: int,
    rank: int,
    batch_size_per_gpu: int = 16,
    image_size: int = 224,
) -> DataLoader:
    """
    Synthetic data for demonstration. Replace with your real dataset.

    Key: DistributedSampler partitions data across ranks (same as DDP).
    FSDP does NOT change data loading — only model parallelism changes.
    """
    # Synthetic dataset for reproducible benchmarking
    dataset = SyntheticImageDataset(
        num_samples=10_000,
        image_size=image_size,
        num_classes=1000,
    )

    sampler = DistributedSampler(
        dataset,
        num_replicas=world_size,
        rank=rank,
        shuffle=True,
    )

    return DataLoader(
        dataset,
        batch_size=batch_size_per_gpu,
        sampler=sampler,
        num_workers=4,
        pin_memory=True,
        drop_last=True,  # Avoid uneven batches across ranks
    )


class SyntheticImageDataset(torch.utils.data.Dataset):
    """Generates random tensors. Zero I/O overhead for benchmarking."""

    def __init__(self, num_samples: int, image_size: int, num_classes: int):
        self.num_samples = num_samples
        self.image_size = image_size
        self.num_classes = num_classes

    def __len__(self) -> int:
        return self.num_samples

    def __getitem__(self, idx: int) -> tuple[torch.Tensor, int]:
        image = torch.randn(3, self.image_size, self.image_size)
        label = torch.randint(0, self.num_classes, (1,)).item()
        return image, label

Data loading is unchanged from DDP. DistributedSampler partitions data across ranks. Each rank processes its shard of the batch. FSDP only changes how the model is distributed, not the data.

Section 7: Training Loop

def train_one_epoch(
    model: nn.Module,
    dataloader: DataLoader,
    optimizer: torch.optim.Optimizer,
    epoch: int,
    local_rank: int,
) -> dict[str, float]:
    """
    Standard training loop. Almost identical to DDP — FSDP2 is transparent.

    Key differences from DDP:
    1. No loss.backward() + optimizer.step() changes
    2. No GradScaler (FSDP2's mp_policy handles it)
    3. No manual gradient sync (FSDP2 handles via reduce-scatter)
    """
    model.train()
    total_loss = 0.0
    num_batches = 0
    start_time = time.time()

    for batch_idx, (images, labels) in enumerate(dataloader):
        # Move data to local GPU
        images = images.to(local_rank, non_blocking=True)
        labels = labels.to(local_rank, non_blocking=True)

        # Forward pass
        # Under the hood: each FSDP unit's pre-forward hook fires,
        # triggering all-gather. The model sees full fp16 parameters.
        outputs = model(images)
        loss = nn.functional.cross_entropy(outputs, labels)

        # Backward pass
        # Under the hood: pre-backward hooks fire (all-gather params again),
        # autograd computes gradients, post-backward hooks fire (reduce-scatter).
        loss.backward()

        # Optimizer step
        # Operates on SHARDED fp32 master weights + SHARDED fp32 grads.
        # No communication here — purely local.
        optimizer.step()
        optimizer.zero_grad()

        total_loss += loss.item()
        num_batches += 1

        if batch_idx % 10 == 0 and local_rank == 0:
            print(
                f"  [Epoch {epoch}][Batch {batch_idx}/{len(dataloader)}] "
                f"Loss: {loss.item():.4f}"
            )

    elapsed = time.time() - start_time
    avg_loss = total_loss / max(num_batches, 1)
    throughput = (num_batches * dataloader.batch_size) / elapsed

    return {"avg_loss": avg_loss, "throughput_img_per_sec": throughput, "elapsed_sec": elapsed}
This looks almost identical to a DDP training loop. That's the point. FSDP2's composable API means your training loop doesn't know or care that parameters are sharded. The hooks handle all communication transparently. The only visible difference: no GradScaler, no model.module accessor (the model isn't wrapped).

Section 8: Optimizer Construction

def build_optimizer(model: nn.Module, lr: float = 1e-4) -> torch.optim.Optimizer:
    """
    Build AdamW on the FSDP2 model's parameters.

    Key detail: After fully_shard(), model.parameters() yields DTensors
    with Shard(0) placement. The optimizer stores states (m, v) as local
    shards — it never sees or allocates the full parameter.

    Memory per rank for optimizer:
      - param shard: P/N × 4 bytes (fp32 master, stored by FSDP)
      - adam_m shard: P/N × 4 bytes
      - adam_v shard: P/N × 4 bytes
      Total: P/N × 12 bytes  (vs. P × 12 bytes in DDP)
    """
    return torch.optim.AdamW(
        model.parameters(),
        lr=lr,
        weight_decay=0.05,
        betas=(0.9, 0.999),
    )
Subtle but important: The optimizer is constructed AFTER fully_shard(). This means model.parameters() returns sharded DTensors. The optimizer allocates exp_avg and exp_avg_sq buffers matching the local shard shape, not the global shape. This is where the memory savings for optimizer states come from — it happens automatically, no special optimizer needed.

Section 9: Main Entry Point

def main() -> None:
    # --- Distributed setup ---
    local_rank, world_size = setup_distributed()

    if local_rank == 0:
        print(f"World size: {world_size}")
        print(f"PyTorch version: {torch.__version__}")
        print(f"CUDA device: {torch.cuda.get_device_name(local_rank)}")

    # --- DeviceMesh ---
    # 1-D mesh: all GPUs in one flat shard group
    # For multi-node HSDP, we'll switch to 2-D mesh in Lesson 009
    mesh = init_device_mesh("cuda", (world_size,))

    if local_rank == 0:
        print(f"DeviceMesh: {mesh}")

    # --- Model ---
    model = build_model()

    if local_rank == 0:
        param_count = sum(p.numel() for p in model.parameters())
        print(f"Model parameters: {param_count:,}")
        mem_model_prop = param_count * 16  # bytes, mixed-precision AdamW
        print(f"Model-proportional memory (DDP): {mem_model_prop / 1e9:.2f} GB per GPU")
        print(f"Model-proportional memory (FSDP, {world_size} GPUs): "
              f"{mem_model_prop / world_size / 1e9:.2f} GB per GPU")

    # --- Mixed precision policy ---
    mp_policy = get_mixed_precision_policy()

    # --- Apply FSDP2 ---
    model = apply_fsdp2(model, mesh=mesh, mp_policy=mp_policy)

    if local_rank == 0:
        # After sharding, parameters are DTensors
        first_param = next(model.parameters())
        print(f"Parameter type after sharding: {type(first_param)}")
        print(f"Global shape: {first_param.shape}")
        print(f"Local shard shape: {first_param._local_tensor.shape}")
        print(f"Placement: {first_param.placements}")

    # --- Optimizer (AFTER sharding) ---
    optimizer = build_optimizer(model)

    # --- Data ---
    dataloader = build_dataloader(
        world_size=world_size,
        rank=dist.get_rank(),
        batch_size_per_gpu=16,  # 16 per GPU × 4 GPUs = 64 effective batch
    )

    # --- Training ---
    num_epochs = 3
    for epoch in range(num_epochs):
        dataloader.sampler.set_epoch(epoch)  # Shuffle differently each epoch

        metrics = train_one_epoch(model, dataloader, optimizer, epoch, local_rank)

        if local_rank == 0:
            print(
                f"Epoch {epoch} complete: "
                f"loss={metrics['avg_loss']:.4f}, "
                f"throughput={metrics['throughput_img_per_sec']:.1f} img/s, "
                f"time={metrics['elapsed_sec']:.1f}s"
            )

    # --- Memory report ---
    if local_rank == 0:
        peak_mem = torch.cuda.max_memory_allocated(local_rank) / 1e9
        print(f"\nPeak GPU memory: {peak_mem:.2f} GB")

    cleanup_distributed()


if __name__ == "__main__":
    main()

The Complete Script

Here's everything assembled into one copy-paste-ready file:

"""
train_fsdp2.py — ViT-Huge/14 training with FSDP2 on V100-32GB GPUs.

Launch (single node, 4 GPUs):
    torchrun --standalone --nproc_per_node=4 train_fsdp2.py

Requirements:
    torch >= 2.4.0 (2.5+ recommended)
    timm >= 1.0.0
"""
import os
import time
from typing import Optional

import torch
import torch.nn as nn
from torch.utils.data import DataLoader, DistributedSampler

from torch.distributed._composable.fsdp import fully_shard, MixedPrecisionPolicy
from torch.distributed.device_mesh import init_device_mesh
import torch.distributed as dist
from torch.distributed import init_process_group, destroy_process_group

import timm


# ─── Distributed Setup ───────────────────────────────────────────────────────

def setup_distributed() -> tuple[int, int]:
    init_process_group(backend="nccl")
    local_rank = int(os.environ["LOCAL_RANK"])
    world_size = dist.get_world_size()
    torch.cuda.set_device(local_rank)
    return local_rank, world_size


def cleanup_distributed() -> None:
    destroy_process_group()


# ─── Model ────────────────────────────────────────────────────────────────────

def build_model() -> nn.Module:
    model = timm.create_model(
        "vit_huge_patch14_224",
        pretrained=False,
        num_classes=1000,
    )
    return model


def apply_fsdp2(
    model: nn.Module,
    mesh: "DeviceMesh",
    mp_policy: MixedPrecisionPolicy,
) -> nn.Module:
    # Per-block sharding: one FSDP unit per transformer block
    for block in model.blocks:
        fully_shard(block, mesh=mesh, mp_policy=mp_policy)

    # Root-level shard for remaining parameters
    fully_shard(model, mesh=mesh, mp_policy=mp_policy)

    return model


# ─── Mixed Precision ──────────────────────────────────────────────────────────

def get_mixed_precision_policy() -> MixedPrecisionPolicy:
    return MixedPrecisionPolicy(
        param_dtype=torch.float16,
        reduce_dtype=torch.float32,

# ─── Main ─────────────────────────────────────────────────────────────────────

def main() -> None:
    local_rank, world_size = setup_distributed()

    if local_rank == 0:
        print(f"World size: {world_size}")
        print(f"PyTorch: {torch.__version__}")
        print(f"Device: {torch.cuda.get_device_name(local_rank)}")

    # 1-D mesh: flat sharding across all GPUs
    mesh = init_device_mesh("cuda", (world_size,))

    # Build model on CPU
    model = build_model()

    if local_rank == 0:
        n_params = sum(p.numel() for p in model.parameters())
        print(f"Parameters: {n_params:,}")
        print(f"Memory per GPU (DDP):  {n_params * 16 / 1e9:.2f} GB")
        print(f"Memory per GPU (FSDP): {n_params * 16 / world_size / 1e9:.2f} GB")

    # Apply FSDP2
    mp_policy = get_mixed_precision_policy()
    model = apply_fsdp2(model, mesh=mesh, mp_policy=mp_policy)

    if local_rank == 0:
        p = next(model.parameters())
        print(f"After sharding — type: {type(p).__name__}, "
              f"global: {list(p.shape)}, local: {list(p._local_tensor.shape)}, "
              f"placement: {p.placements}")

    # Optimizer (on sharded params)
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4, weight_decay=0.05)

    # Data
    dataloader = build_dataloader(
        world_size=world_size,
        rank=dist.get_rank(),
        batch_size_per_gpu=16,
    )

    # Train
    for epoch in range(3):
        dataloader.sampler.set_epoch(epoch)
        metrics = train_one_epoch(model, dataloader, optimizer, epoch, local_rank)
        if local_rank == 0:
            print(
                f"Epoch {epoch}: loss={metrics['avg_loss']:.4f}, "
                f"{metrics['throughput_img_per_sec']:.0f} img/s, "
                f"{metrics['elapsed_sec']:.1f}s"
            )

    # Report peak memory
    peak_gb = torch.cuda.max_memory_allocated(local_rank) / 1e9
    print(f"[Rank {local_rank}] Peak memory: {peak_gb:.2f} GB")

    cleanup_distributed()


if __name__ == "__main__":
    main()

Anatomy Recap: What Happens Under the Hood

When outputs = model(images) executes:

  1. Root module's pre-forward hook fires → all-gathers patch_embed, pos_embed, cls_token
  2. Patch embedding + position encoding runs
  3. Root's post-forward hook → frees those params (back to shard)
  4. For each block i in 0..31:
    1. Block i's pre-forward hook → all-gathers block i's parameters
    2. Simultaneously: prefetches block i+1's all-gather (if forward_prefetch=True)
    3. Block i's forward runs (attention + MLP in fp16)
    4. Block i's post-forward hook → frees unsharded params
  5. Classification head runs (part of root FSDP unit)

Backward is the reverse, with reduce-scatter of gradients after each block's grad computation.

Common Mistakes

MistakeSymptomFix
Calling model.cuda() before fully_shard() OOM on large models; defeats sharding for memory Build on CPU, let fully_shard() handle placement
Sharding root before children All params in one FSDP unit → peak memory = full model Always shard leaf/children first, root last
Constructing optimizer before fully_shard() Optimizer stores full-size buffers → no memory savings Always: build model → shard → build optimizer
Using torch.distributed.fsdp.FullyShardedDataParallel FSDP1 behavior, incompatible with FSDP2 features Import from torch.distributed._composable.fsdp
Forgetting drop_last=True in DataLoader Ranks get different batch sizes on last batch → NCCL hang Always drop_last=True with distributed training

Check Your Understanding

Q1: Why must the optimizer be constructed AFTER fully_shard()?

Correct. After fully_shard(), parameters are DTensors with local shard shape [P/N, ...]. The optimizer calls torch.zeros_like(param) to allocate m and v buffers, which will be shard-sized. If you construct the optimizer before sharding, it sees full-size parameters and allocates full-size state — negating the memory benefit.

Q2: With 4 GPUs and ViT-Huge (32 blocks sharded individually), what is the peak "unsharded parameter" memory during forward?

Correct. Each FSDP unit (one transformer block) is independently all-gathered and freed. During forward, only one block's full parameters exist at a time: ~20M params × 2 bytes (fp16) = ~38 MB. Note: with prefetching enabled, briefly two blocks may be unsharded simultaneously (~76 MB) — option C is also plausible in practice, but the standard accounting considers one unit at a time as the steady-state, with the prefetch being an overlapping transient.

Q3: Why do we set reduce_dtype=torch.float32 specifically for V100?

Correct. fp16 has a 5-bit exponent → dynamic range of ~6×10⁻⁸ to 65504. Small gradients (common in deep networks with many layers) can underflow to zero during summation across ranks. bf16 (8-bit exponent) doesn't have this issue. Since V100 lacks bf16 hardware support, we reduce-scatter in fp32 to preserve gradient precision. The optimizer could technically handle fp16 inputs (it would just upcast), but the damage is already done if gradients underflowed during the collective.

Key Takeaways

  1. Build order: model (CPU) → fully_shard (children first, root last) → optimizer → dataloader → train
  2. The training loop is nearly identical to DDP. No GradScaler, no model.module, no manual gradient sync. FSDP2 is transparent during training.
  3. MixedPrecisionPolicy replaces the AMP autocast + GradScaler pattern. On V100: param_dtype=fp16, reduce_dtype=fp32.
  4. DeviceMesh is a 1-D tensor of GPU IDs for simple full-sharding. Multi-dimensional meshes enable HSDP.
  5. Data loading is unchanged from DDP. DistributedSampler, pin_memory, drop_last — all the same.
